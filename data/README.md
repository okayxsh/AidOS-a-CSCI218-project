# Scenario data — provenance

All scenarios in `data/scenarios/` are **synthetic**, created for the CSCI218 AidOS academic simulator.
They are not real disaster, medical, or humanitarian case records, and every scenario file must declare
`"synthetic": true`. Zone names, populations and ratings are invented.

Real data may only be added if it is explicitly authorized and anonymized, with its source and
permission recorded here.

## Schema (version 1.0)

Validated by `apps/api/aidos/domain/models.py` and `validation.py` when loaded. Invalid files are
rejected with a located message, never partially loaded.

| Field | Meaning |
|---|---|
| `schema_version` | `"1.0"` |
| `scenario_id` | lower-case id, `[a-z0-9][a-z0-9_-]*` |
| `title`, `description` | human-readable text |
| `seed` | integer recorded for reproducibility |
| `synthetic` | must be `true` |
| `step` | simulation step (0 at load) |
| `resources[]` | `{id, label, unit}`; the order is the canonical resource order |
| `stock` | `resource_id -> non-negative integer`, required for every resource |
| `zones[]` | `{id, name, arrival_order, severity, vulnerability, time_criticality, activation_step?, population?, demand}` |

Ratings are 0–10 simulated inputs, not triage grades. `demand` maps resource ids to non-negative
integers; unknown resource ids, duplicate ids, negative units and more than 50 zones are rejected.
A zone with `activation_step` greater than `step` is not yet active and is excluded from summaries
and allocations.

## Scenarios

| File | Purpose |
|---|---|
| `triage-demo-001.json` | Default demo (spec Section 4 example): 3 zones, 3 resources, every resource short |
| `no-scarcity.json` | Stock covers every request; every policy must meet demand exactly |
| `late-critical-arrival.json` | The most critical zone arrives last; arrival order and urgency disagree |
| `zero-stock.json` | Empty depot; every allocation must be zero with a reason |
| `coastal-storm-005.json` | 6 zones, 4 resources, severe scarcity, one zone not yet active |
| `medical-escalation-006.json` | Medical kits short; the least urgent zone is the one the demo escalates (Stage 3) |
| `supply-arrival-007.json` | Water and medical kits short; a shipment covers the water shortage (Stage 3) |
| `severe-shortage-008.json` | 5 zones, 4 resources, stock about a third of requests (Stage 3) |
| `competing-emergency-009.json` | A critical zone is scheduled for step 1; advancing time brings it in (Stage 3) |

## Simulation scripts

`simulations/triage-demo-escalation.json` is a replay document (`aidos-simulation` 1.0, see `docs/simulation/replay.md`) generated by the engine: the live-demo event sequence on `triage-demo-001` with the outcome hash of every step. A test replays it and fails if any recorded outcome no longer matches.
